==============================================================================
TEXT REPRESENTATION - CountVectorizer (Bag of Words)
source: data/processed/tweets_preprocessed_augmented.csv   (699 documents)
==============================================================================

[1] WHAT THIS DOES

    A model cannot read text, only numbers. CountVectorizer builds a table:

        one ROW per document (tweet)
        one COLUMN per distinct term in the whole corpus
        each CELL = how many times that term appears in that document

    That table is the "document-term matrix", and the representation is called
    Bag of Words because it records WHICH words occur and HOW OFTEN, but throws
    away the order they came in.

    N-grams are how word order is partly recovered. An n-gram is a run of n
    consecutive words, so the vectoriser can treat "not good" as its own column
    instead of separate "not" and "good" columns that lose the connection.

[2] WORKED EXAMPLE  (3 tiny documents, unigrams)
                   bad  game  good  not
doc1: 'good game'    0     1     1    0
doc2: 'bad game'     1     1     0    0
doc3: 'not good'     0     0     1    1

    doc3 scores 1 for 'good' and 1 for 'not', but nothing links them -
    to a unigram model doc1 and doc3 both simply 'contain good'.
    That is exactly the weakness bigrams fix:
      bad game  good game  not good
doc1         0          1         0
doc2         1          0         0
doc3         0          0         1

    'not good' is now its own feature, and doc3 is distinguishable.


[3] THE FOUR REPRESENTATIONS  (min_df=1)
    setting      ngram_range    features         matrix  sparsity   meaning
    unigram      (1, 1)              981        699x981    98.9%   single words: 'good', 'game'
    bigram       (2, 2)             2435       699x2435    99.6%   word pairs: 'not good', 'red dead'
    trigram      (3, 3)             2874       699x2874    99.7%   word triples: 'red dead redemption'
    uni+bigram   (1, 2)             3416       699x3416    99.4%   both, the usual choice for sentiment

    'sparsity' = share of cells that are zero. Most tweets contain almost
    none of the corpus vocabulary, so the matrix is mostly empty - which is
    why scikit-learn stores it in a sparse format rather than a full table.
    Notice the feature count explodes as n grows while each feature gets
    rarer: that is why unigrams+bigrams is the usual compromise.
